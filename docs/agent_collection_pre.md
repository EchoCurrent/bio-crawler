# 发布前补充采集规范 (补搜 wave 专用, 所有子 agent 必读)

与首轮广度的区别：**时间窗口严格限定 2026-11-16 至 2026-11-23（最近 7 天）**。
目标是给日报补充最新鲜的内容，不是铺开广度。

## 工作流程
1. 按任务给定的渠道清单/关键词检索，只收 7 天内发布（或官网标注最新）的内容。
2. 每收几条就追加写入 JSONL，不要攒到最后一次性写。

## 输出：JSONL（每行一个 JSON，UTF-8），字段与首轮完全一致
```json
{
  "title": "条目标题（原文标题，≤80字）",
  "url": "真实URL，必须实际在页面/搜索结果里见过",
  "source": "来源名称",
  "source_type": "journal | website | wechat | news | official | preprint",
  "category": "生物医学",
  "subtopic": "子方向名（任务里给你的那个）",
  "summary": "一句话中文摘要，≤50字",
  "relevance": "high | medium",
  "published_time": "YYYY-MM-DD 或空",
  "via": "发现路径，如 'NEJM 最新一期目录' / 'NMPA 官网'"
}
```

## 铁律
1. 绝不编造 URL；只记录真实见过的链接。
2. 超过 7 天窗口的内容**不要**（除非任务特别说明）。
3. 期刊目录页（TOC）抓不到时，退而用搜索补；若某刊整刊都抓不到，在汇报 notes 里说明。
4. 标题中文，摘要中文；英文原标题保留原文。

## 完成后汇报（中文）
文件路径、条目数、high 数、覆盖渠道、抓不到/有问题的渠道清单。不要贴 JSONL 全文。
